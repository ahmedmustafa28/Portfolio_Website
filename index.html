Olympics Data Analysis Web App

[Streamlit]
  • Built a 4-module analytics platform (Medal Tally, Overall Analysis, Country-Wise, and Athlete-Wise performance) covering 120+ years of Olympic data.
  • Processed and analyzed 271,116+ athlete records (athlete_events.csv, noc_regions.csv) using Pandas; built interactive Plotly dashboards and Seaborn heatmaps to surface gender participation trends, event evolution, and top-athlete profiling.
Technical Architecture & Decisions
Raw Olympic records (CSV, 271,116 rows) ↓ Summer Games filter + NOC region merge (Pandas) ↓ Team-medal deduplication for country tallies ↓ Plotly line charts, Seaborn heatmaps, Streamlit UI
  • Problem & decision: team events (hockey, football) list every medal-winning athlete as a separate row, which inflates national tallies. The tally helper drops duplicates on Team, NOC, Games, Year, City, Sport, Event, Medal before summing, while athlete-level views keep the full rows.
  • Engineering trade-off: the whole dataset is held as an in-memory DataFrame behind st.cache_data, so there is no database to run, but the app has to fit within the Streamlit Cloud container memory.

WhatsApp Chat Analyzer

[Streamlit]
  • Built an NLP-powered web app that ingests exported WhatsApp chat text files (media excluded) and generates 7+ analytical insights: activity timelines, emoji analysis, word clouds, weekly heatmaps, and per-user behavioral breakdowns across multi-user group chats.
  • Designed a 3-module pipeline (preprocessor → helper → app) with a custom Hinglish stop-word filter to support accurate multi-user text analysis.
Technical Architecture & Decisions
Raw chat export (.txt) uploaded in the browser ↓ Regex split on timestamps, author/message separation (preprocessor.py) ↓ Date features, Hinglish stop-word filter, URL and emoji extraction (helper.py) ↓ Timelines, activity heatmap, word cloud, emoji share (Matplotlib, Seaborn)
  • Problem & decision: exports differ between devices, and some insert a narrow no-break space before AM/PM. The timestamp regex accepts both separators, and lines without an author are tagged as group notifications so they do not count as a user.
  • Engineering trade-off: the upload is parsed in memory for the session and never written to disk, which protects private chats but means the file must be re-uploaded after a refresh.

Spam Email Detector

[LIVE]
  • Built a text classification model to distinguish spam from legitimate emails, applying NLP preprocessing including tokenization, stop-word removal, and TF-IDF vectorization.
  • Achieved 97.75% accuracy, 99.21% precision, 83.89% recall, and a 90.91% F1-score with a Random Forest classifier (best of 3 models compared) on the test set.

Technical Architecture & Decisions
SMS spam dataset (spam.csv, ham/spam labels) ↓ clean_text: lowercase, strip punctuation and digits, NLTK tokenize, stop-words, Porter stemming ↓ TF-IDF (3,000 features), stratified 80/20 split ↓ Naive Bayes vs Logistic Regression vs Random Forest, best by F1 saved with metrics JSON
  • Problem & decision: the dataset is imbalanced, so train.py picks the best model by F1-score rather than accuracy. Random Forest (100 trees) won on F1, and its metrics are written to models/model_metadata.json, which the app reads to show the comparison table.
  • Engineering trade-off: the same clean_text function is shared by training and inference so the live app tokenizes exactly as the model was trained; NLTK resources are downloaded on first run.

House Price Prediction

[LIVE]
  • Built a regression model to predict property prices from features such as location, area, and amenities, applying feature engineering and data cleaning.
  • Achieved an RMSE of $100,444 and an R² of 0.918 with a Linear Regression model (best of 2 models compared) on the test set.

Technical Architecture & Decisions
Kaggle USA Housing dataset (5,000 rows, Address column dropped) ↓ Five numeric features: area income, house age, rooms, bedrooms, population ↓ StandardScaler, 80/20 split, Linear Regression vs Random Forest ↓ Best model by R² saved with scaler; Streamlit app with Plotly charts
  • Problem & decision: the relationships in this dataset are close to linear, so plain Linear Regression beat a 100-tree Random Forest on the held-out set (R² 0.918 vs 0.882) and was kept as the simpler model.
  • Engineering trade-off: the app reports each estimate with a ±MAE range ($80,879, stored in models/metadata.joblib) instead of a single number, and overlays the inputs on the market scatter plots so the prediction can be sanity-checked against real listings.
